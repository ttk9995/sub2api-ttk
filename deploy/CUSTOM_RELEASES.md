# 自定义版本更新

本站自定义功能维护在 `ttk9995/sub2api-ttk` 的 `custom` 分支。官方完整二进制包含前端，直接安装官方更新会覆盖用户 API 密钥测试、后台模型测试和鹈鹕 SVG 预览。

自定义发布使用 `v<上游版本>-ttk.<修订号>`，例如 `v0.2.14-ttk.1`。保留上游版本号用于核对安全修复，同一上游版本的修订号用于识别自定义修复。GitHub Release 必须标记为正式发布，并包含目标平台压缩包和 `checksums.txt`；只同步官方发布、只推送分支或只发布 Docker 镜像不够。

后台更新只读取本仓库。安装自定义版本后，更新和下载式回退均排除没有 `-ttk.<修订号>` 的历史官方镜像发布；旧更新来源的缓存也不会继续使用。发布前应在自定义分支合并目标上游版本，验证测试功能及上游变更，再构建同一提交的完整程序。

Docker 镜像由发布流程写入 `ghcr.io/ttk9995/sub2api`。服务器使用镜像部署时应固定已验证的自定义版本。应用内更新会修改容器可写层中的二进制，不会改变镜像标签；核对运行版本时需同时检查 `docker inspect` 和 `/app/sub2api --version`。重建容器前应保存当前实际运行二进制，以便失败时恢复到更新后的版本。

`0.2.14-ttk.1` 恢复此前的测试功能，合入官方 `0.2.14` 的管理员初始化及 EasyPay 安全修复。本次不涉及数据库迁移。
